# Changelog

All notable changes to this project will be documented in this file.

## [Unreleased]

### Features
- **Client** — A project switch that takes longer than a moment shows a "Switching project…" note while the previous project stays on screen. A failed switch returns to the previous project with an error message
- **Client** — The project list now comes from the host on the browser and the desktop alike: the sidebar and the project switcher are fed only by the `projects` watch, and adding, renaming, recolouring, archiving, restoring, deleting and choosing the host default go to the host through the same `/ws` commands, so a change made on one device shows up on the others without a refetch. What the host never sees (icon, git state, worktrees, default shell, environment variables, groups, order) stays on the device in `project-prefs`; secret values stay in secure storage. Switching project writes only this device's `active-project`; a device with none lands on the host default, else the first project that is not archived. On the first desktop start after the upgrade the old `projects` record is imported into the host once and then deleted. Deleting, archiving or moving the folder of a project that still has chats or terminals running asks first ("2 chats and 1 terminal are still running...") and only on your confirmation lets the host stop them. The desktop commands `remote_sync_projects` and `set_host_default_project`, the renderer's full-list push, the web diff-to-HTTP autosave and the unused renderer project cascade are removed
- **Server** — A project's root folder can now be changed through the registry: `update_project` (and `PUT /projects/{id}`) takes an optional `path`, validated and saved like the one an add takes. Moving the root of a project that still has live chats or terminals is refused as `project_busy` listing them, and `cascade: true` lets the host stop them first, the same as for archiving; the folder the project already has is not a move, and a refused move changes nothing
- **Desktop** — The desktop renderer now speaks the same `/ws` contract as the browser over one ordered Tauri channel, so sequence numbers, `commandId` receipts, cursors and the state watches work the same on both. The old `acp:events` batches, the `TauriEventSink` and the per-domain `acp_*` session, agent, prompt, catalog and install commands are removed; only host-local commands (probes, MCP OAuth, factory key, timeouts, registry snapshot) remain
- **Web** — A saved value that grows without bound is trimmed to the host's 256 KiB value cap before it is written, oldest first: terminal layouts cut each terminal's oldest scrollback and transcript by the same share (the newest output survives, and the live terminal keeps all of it), snapshot lists cut the output of the oldest snapshots first and remove a whole snapshot only when nothing else makes room (a warning toast says so, and the newest snapshot always stays), and the command history and the recent file mentions drop their oldest entries. Text you typed (chat and launcher drafts) is never trimmed. A write the host or the facade refuses now shows one toast per failure code and key every 30 seconds (value too large, device storage full, value not read yet, host write failure, lost compare-and-set race after the SSH profile retries), through the new `persistenceApi.onPersistenceError` bus mounted in both renderer roots. Every persistence key now lives in `PersistenceKeys` (a test checks each one against its scope). The crash-recovery session moves from its own `termul-sessions.json` file into the facade key `sessions/auto-save`: the first read, write or clear moves a leftover entry once and deletes it, and the old file is never read again. The desktop store flushes pending writes when the window is hidden or closed, like the web store
- **Web** — A pending approval or question now waits for a person for as long as its session exists: the 60-second ticket timeout and the deny after the last viewer disconnects are gone, so a phone that reconnects hours later answers by `ticketId`; only an answer (the first wins, a later one reads `already_resolved`), the end or cancel of the turn, the session closing or the agent dying releases it, and the session's next queued approval is promoted at once; the renderer no longer infers a "denied because this device disconnected" notice, and `runtimePolicy` drops `permissionReconnectGraceMs` (`--permission-timeout` and `--permission-reconnect-grace` still parse with a startup warning)
- **Server** — A live PTY now ends only by an explicit kill, a process exit or host shutdown. Closing a pane or a browser tab only detaches it; the PTY keeps running and the project terminal list still shows it. The inactivity reaper and the web-listed reaper are gone, together with the `terminal_update_orphan_detection`, `terminal_add_renderer_ref`, `terminal_remove_renderer_ref` and `terminal_set_protected` commands and the matching `/terminal/ws` requests (`add_renderer_ref`, `remove_renderer_ref`, `set_protected`, `update_orphan_detection`), which are now unknown requests. A PTY whose process has exited stays tracked for 10 minutes so a late client still replays its output, then the host removes it; this sweep never touches a live PTY. The Settings "Orphan Detection" options are removed, and old persisted `orphanDetectionEnabled` / `orphanDetectionTimeout` values are dropped on load
- **Server** — The host enforces the terminal caps on every surface (desktop, shared-live, `termul-server` and the browser): a spawn over the per-project limit or the global 30 is refused with the stable code `TERMINAL_LIMIT` on `/terminal/ws` and in the desktop `terminal_spawn` reply, the message names both limits, and the refused spawn creates no PTY, claim or event and holds no slot. Concurrent spawns cannot both pass the check. Detached PTYs count; a PTY whose process has exited counts toward neither cap. The per-project limit is `--max-terminals-per-project` / `TERMUL_MAX_TERMINALS_PER_PROJECT` (default 10); the desktop reads the same variable. The renderer no longer counts terminals itself: the Settings "Max Terminals Per Project" option is removed (an old saved value is dropped on load), and the host message is shown when a spawn or a restore is refused
- **ACP** — A failed agent start or a crash now logs the agent kind, the command's file name and the last lines the agent wrote to stderr (a bounded tail with keys, tokens and bearer values masked; arguments and environment never appear), and a start failure carries that tail in its error detail. Provider refusals get stable codes: a quota or usage limit, a session limit and a rejected request answer `provider_quota_exceeded`, `provider_session_limit` and `provider_request_rejected` on `/ws` (`ACP_PROVIDER_*` prefix on desktop), and `agent_error` carries `providerCode`. The chat classifies by that code first, shows a plain message for a limit, and keeps the wording heuristics only for hosts that send no code
- **Server** — MCP servers and OAuth sign-in now name the project they act for instead of hanging off one host default project: `GET`/`PUT /mcp-servers?projectId=` read and write that project's `.termul/mcp-servers.json`, and OAuth start, status and disconnect take `projectId` (start only accepts a server URL listed in that project; saved sign-in tokens stay shared per server URL). A project that is unknown, archived or has no folder is refused `NOT_FOUND`. The desktop copies its MCP list to the active project's file. There is no single host project root any more: `--project-root` (and `$TERMUL_PROJECT_ROOT`) still parse for one more release with a startup warning and only seed one project while the registry is empty, the desktop never seeds one, and the onboard wizard no longer asks for a root.
- **Editor** — A project switch now writes pending editor autosaves (best effort; a busy or failing file stays unsaved and its draft is kept) before the switch continues. A restored unsaved draft whose file changed on disk after the draft was taken is no longer dropped: the file opens with the disk content and a banner offers `Keep my draft` or `Use disk version`. A file with such a draft counts as unsaved when you close it
- **Client** — Each project keeps its own pane tree. Switching to a project you already opened swaps the tree without reading or rebuilding it, and a first visit builds the tree off-screen and shows it in one step. All switches go through one latest-wins request: a newer pick or an explicit open replaces an older one, a late result for a project you already left is dropped, and a failed switch returns to the project that stays on screen. Live terminals and chats keep running in the projects you leave
- **Server** — The host offers three more watches and retires its last `seq = 0` events: `fs` (scope = project id, one debounced batch of changed paths per delta, replacing `watch_project`/`unwatch_project`/`fs_changed`/`fs_watch_ended`), `store` (scope = key, the value after each write or delete) and `terminals` (scope = project id, the terminals including detached ones, without claim credentials). `browser_open_request` is an `agents` delta and `worktree_branch_renamed` a `chat_history` delta, so the relay sends no `seq = 0` event except the `auth_required` handshake frame. A delta dropped for a full queue leaves a revision gap and a resync marker, and the client rebuilds from fresh state. The client exposes `watchStoreKey`. `WS_PROTOCOL_VERSION` is 7; clients reload on mismatch
- **Server** — The web client now reads the state watches: the project switcher rebuilds its list from the `projects` watch, the chat-history sidebar installs the `chat_history` index (and refetches on a delta), and the agent store reconciles its roster from the `agents` watch, so each is rebuilt from fresh state after a missed delta or a reconnect. The `projects_changed` and `chat_history_changed` nudges and the sid-less `agent_spawned`/`agent_crashed`/`agent_error`/`agent_disconnected` `seq = 0` events are gone from the relay. `WS_PROTOCOL_VERSION` is now 6
- **Server** — The host offers state watches (`watch`/`unwatch`) for the project list, the chat-history index and the agent roster: one full-state frame, then deltas under a contiguous `(hostEpoch, n)` revision, delivered once per socket even when it has no session subscription. A delta the host cannot queue leaves a revision gap, and a resync marker makes sure the client sees it. The web transport routes the frames to a new `WatchClient`, which resubscribes on a skipped revision, a new host epoch or a reconnect. The existing `projects_changed`, `chat_history_changed` and agent roster events still arrive until clients switch to the watches. `WS_PROTOCOL_VERSION` is now 5
- **Server** — The project list now has one owner per host: a durable registry that every client and the desktop share. `termul-server` keeps it in its projects file and the desktop in `projects.json` next to `store.json`; each change is written to disk atomically before it takes effect, so a failed write changes nothing and every device sees the same list. Stopping shared-live no longer empties the desktop's list. Adding, updating, archiving and removing a project go through the same commands over `/ws` (`add_project`, `update_project`, `remove_project`, `set_default_project`), HTTP and the desktop; repeating an add or removing an unknown project is fine, and adding an existing id with a different folder is refused as `duplicate`. Removing or archiving a project that still has live chats or terminals is refused with the new `project_busy` error (HTTP `PROJECT_BUSY`), whose `details` list the chat and terminal ids; sending `cascade: true` (`?cascade=true` on `DELETE /projects/{id}`) makes the host stop them first and then remove or archive the project, and no new chat or terminal can start in that project meanwhile. A chat that was already starting when the cascade began is stopped when it finishes starting; if that stop fails, the client that started it gets `project_busy` without a chat id and the chat stays open until someone closes it. Archiving or removing the default project clears the default. `projects.json` is schema 4 (older files load and are backed up before the first write, newer ones are refused); a corrupt file is set aside as `.corrupt-<time>.bak` and the desktop starts with an empty list. A new desktop command, `project_registry_import`, lets the app carry its previous project list into the registry exactly once without overwriting anything
- **Server** — Slow phones no longer cost the host unbounded memory: every session subscription feeds its connection through a bounded channel, a dropped LOSSY event is followed by a `gap` frame as soon as the subscriber's channel drains, a reliable event that finds no room closes the connection so the phone resumes by cursor, and the host writes a `heartbeat` frame every 10 s. The web client applies events only when contiguous (a skipped seq installs a snapshot instead of being applied), judges host liveness from received frames instead of a ping round trip, and degrades a single failing session without failing the reconnect. `WS_PROTOCOL_VERSION` is now 4
- **Server** — Session and terminal logs carry a `logEpoch`: `subscribe` and `recover_session_snapshot` return `(logEpoch, headSeq)` (`get_session_cursor` returns them too for a session the host has a log for), and a cursor from another epoch (a non-durable host restarted) or ahead of the log head is answered `stale` and replaced by an atomic snapshot instead of being silently honoured or dropping new events as duplicates. A terminal attach with such a cursor replays its whole retained log with `reset` and the client clears the terminal first. Durable sessions persist the epoch in `metadata.json` (a legacy file gets one on load, written back at once), and the epoch rotates on a restart when the session's seq frontier had run ahead of the disk (a live-only event such as a permission request took a seq the log never held). A terminal attach with a nonzero cursor and no known epoch is treated the same way (replayed in full with `reset`), and the desktop `terminal_attach` command takes the epoch too and clears the terminal on `reset`. `get_session_cursor` leaves `logEpoch`/`headSeq` out for a session the host has no log for. `WS_PROTOCOL_VERSION` is now 3, so clients reload against an older host
- **Commands** — Every mutating command now carries a client-minted `commandId` and the host answers a lost-reply resend with the original outcome instead of running it twice: a shared in-memory receipt ledger covers `/ws` and the Tauri `acp_*` commands (session/agent creates stamp the id on the entity, so a resend after eviction or a host restart finds it), `/terminal/ws` and the desktop `terminal_*` commands (spawn answers a resend with the existing PTY and a fresh claim; per-chunk `write` ids; kill, rotate/revoke claim), the HTTP routes via the `X-Command-Id` header (fs write/rename/copy, git commit/discard/stash/hunks/create-branch, worktree create/rename-branch, ACP install, workspace write) and the matching Tauri domain commands (`commandId` argument). A ledgered command without an id is refused with `invalid_command_id` (`INVALID_COMMAND_ID` on HTTP and terminal replies); `send_prompt` keeps its optional `turnId`. New stable codes: `outcome_unknown` (the host no longer knows whether it ran and will not run it again), `command_conflict` (id reused for another request), `precondition_failed`. Receipts keep the outcome class and, where a resend must answer with the original reply, a bounded reply payload (never request bodies, claims or secrets), outcomes are kept at least `--receipt-retention-secs` (bare ids a multiple longer), and a host start appends `prompt_complete{interrupted}` for every turn a crash left open before any client is accepted. The web client journals each command before sending it (`pending`, `accepted`, `rejected`, `pending-reconcile`): a lost reply is resent with the same id, a definite rejection mints a new one, and "Outcome unknown — check" is shown instead of a failure
- **Web** — Preconditions: `POST /fs/write` takes `expected` (`{"sha256": …}` of the last read, or `"absent"`) and `GET /fs/read` returns `contentHash`; the editor saves with the hash it read and a changed file shows "File changed externally" instead of being overwritten. `POST /git/commit` and the desktop `git_commit` take `expectedHead` and refuse a moved HEAD with `precondition_failed`; commits carry a `Termul-Command-Id` trailer so a resend finds its commit
- **Server** — The web boundary for fs writes from remote peers, git, worktree, search, skills and canvas is now "inside any registered, non-archived project" (cached canonical roots, revalidated on use) instead of one rebindable host root: a phone can work in any registered project, outside every project returns `OUTSIDE_PROJECT_ROOT`, and moving the host default no longer moves the boundary. A synthetic project is seeded from `--project-root` (or the desktop default/home) only while no usable project is registered and is retired when a real one is added. `fs_changed` is now per project: connections send `watch_project`/`unwatch_project` and receive `fs_changed{projectId,root,paths}` only for the projects they watch (refcounted watcher per project, dropped on last unsubscribe, disconnect, or project archive/remove, which also sends `fs_watch_ended`)
- **ACP** — `list_agents` replies carry each live agent's owned-session set (`ownsSession`), so a reloading web client can reuse the host agent that owns a session instead of spawning a duplicate (#837)
- **Server** — One host-owned idle agent reaper per process (the desktop app and `termul-server` each run one) with a single idle window, default 30 min (`--agent-idle-window-secs`, `TERMUL_AGENT_IDLE_REAP_SECS`). An agent is stopped only when the host saw no activity for the whole window: no running turn, no unanswered approval/question/elicitation, no running agent-owned terminal, no reopen in flight. Connections, subscribers and presence never keep an agent alive, and a disconnect never stops one; the agent is re-checked immediately before the stop (#837)
- **ACP** — Killing an agent, the idle reaper and an agent crash are now announced to every connected client as `session_closed` for each live session followed by `agent_disconnected`, both carrying a new `reason` (`killed`, `reaped`, `crashed`, or `closed` for an explicit `close_session`); only process shutdown stays silent. The desktop renderer treats a killed/reaped/closed agent like a local kill instead of showing it as failed
- **ACP** — `close_session` during a running turn cancels the turn and waits for its terminator before closing, so the turn ends with exactly one `prompt_complete` followed by `session_closed`; if the agent does not confirm in time the session is dropped locally and the request fails
- **Server** — One host per data path: the desktop and `termul-server` take an exclusive `File::try_lock` lock on a sidecar (`.termul.lock` in directory stores, `<file>.lock` beside `store.json`/`projects.json`) before opening any store; a second host refuses to start and names the path and, when available, the rival pid. The sidecar is never followed through a symlink
- **Server** — `store.json` is versioned (`{"schemaVersion":1,"data":{…}}`): a legacy bare map is backed up to `store.json.pre-v1-<ts>.bak` before it is migrated, a newer `schemaVersion` is refused and the file left untouched, unknown top-level keys survive rewrites, and the 10 MiB write limit applies to the data payload. Migration backups (including `projects.json.pre-v3-<ts>.bak`) are created owner-only (`0600`) on Unix
- **ACP** — The workspace manifest, ACP catalog and install stores refuse to open a file written by a newer schema instead of overwriting it
- **Desktop** — Shared-live mode serves the desktop's own `store.json` from the desktop data folder, so the desktop and the shared web client see one store
- **Desktop** — A tunnelled shared-live host now requires the bearer token for HTTP, and the shared tunnel link carries `#token=<token>` so the browser can authenticate; the bare tunnel URL is never shared alone
- **Web** — Connection capabilities: `/ws` and `/terminal/ws` resolve a capability set at `authenticate` (carrier, deployment flags, peer address). View-only connections (shared-live deployment, or a non-loopback peer without `--allow-remote-writes`) may read, ping, subscribe and write only `device/<deviceId>/…` store keys; every other mutation is refused with the new stable code `forbidden`. One shared write predicate now guards the HTTP write routes too (including `POST /search/cancel` and `/canvas/open|close|save`)
- **Web** — `respond_permission` / `answer_question` are answered by ticket: the connection need not be subscribed and `agentId` is optional; a later answer to a resolved ticket gets the new stable code `already_resolved` (bounded tombstones). Device presence is tracked per `deviceId` across `/ws` and `/terminal/ws`
- **Git** — Branch switch / checkout and worktree removal (HTTP and desktop commands) are refused with `destructive_op_blocked` while a session whose working directory is inside the target has an active turn
- **Web** — Relay execution model: `/ws` requests run as per-request tasks, in arrival order per entity (one session, agent, terminal, project or store key) and concurrently across entities, so a slow handler (a 120 s install) no longer starves pings, the keepalive or a prompt on another session, and `send_prompt` then `cancel_prompt` on one session cannot reorder. The keepalive watchdog runs on its own timer, so a peer silent past the 75 s pong deadline (300 s after a `background` frame) is closed even while a send to it is stalled. The per-connection outbound queue is bounded (1024 frames) and a peer that stays full for `overflow_tolerance` (default 15) consecutive attempts is closed instead of buffered; replies either queue or close the connection. Stopping the host (desktop shared-live toggle, SIGINT/SIGTERM) now sends `Close(1001 host stopping)` to every open `/ws` and `/terminal/ws` socket and waits for them (bounded; a socket that cannot take the close is dropped after 2 s and stragglers are aborted after 5 s) before `serve` returns. The standalone server then stops agents and terminals; the desktop shared-live toggle only drains sockets and leaves the desktop's agents and terminals running. `/terminal/ws` gets only the host-stop close: its requests are still handled one at a time on that socket, with no independent watchdog. Ordering is per entity key, not global (for example `close_session` and `kill_agent` on one agent run on different queues), ticket answers (`respond_permission`, `answer_question`, `respond_elicitation`) never queue behind other handlers, a connection past 256 in-flight requests is refused with `unsupported`, and an overflow failure is counted at most once per second per connection
- **Server** — One sequence authority per session log: the relay numbers every record, including host-authored titles, agent-switch markers and the shutdown `interrupted` marker, and the persistence writer no longer assigns seq. Sequence assignment, durable enqueue and fan-out to subscribers run as one step, and `subscribe` and snapshot registration happen under the same lock behind a writer barrier, so a title written during a stream can no longer collide with a stream event or arrive out of order.
- **Server** — The web store is scoped and versioned per device (#1073): `store.json` is schema v2 (`{"schemaVersion":2,"data":{key:{v,rev,cid,cmd?,fields?}},"host":{…}}`), keys are `device/<deviceId>/…` (only the authenticated device's own partition, last host arrival wins, stamped with a per-key revision and the writing `clientInstanceId`), `shared/lww/…` (per-field merge against the writer's `baseRevision`; a write to an existing key without one is refused `STORE_BASE_REQUIRED`) or `shared/cas/…` (`expected` + `commandId`; a resend of the same write after a lost reply succeeds); anything else is refused `STORE_KEY_SCOPE`. A v1 store is backed up to `store.json.pre-v2-<ts>.bak`, its shared settings keys move to `shared/*` and every other key is adopted by the first device that connects. A device's partition is capped by `--partition-byte-budget` (default 16 MiB, `STORE_PARTITION_FULL`) and collected after `--partition-gc-age-secs` (default 90 days) without the device connecting; `WS_PROTOCOL_VERSION` is now 7 (reload stale clients)
- **Client** — A chat belongs to the project its session names: opening a chat of another project (a `#/c/<session>` link, a notification, the "needs you" pill) opens it in that project instead of dropping it, and no chat tab is filtered out of a project's panes by ownership any more. A chat's memory is released only when it is in no tab of any project and its session is idle (no turn, queued prompt or pending permission/question), a moment after the last tab closes; chats of projects you switched away from stay loaded, and their agent process is not shut down because their project is off screen
- **Client** — The renderer no longer syncs a workspace manifest with the host (#1073): a project's open files and pane layout are read from and written to the device's own `workspace/<projectId>` record only, so the conflict banner is gone and deleting a project also deletes that record.
- **Server** — The host no longer keeps a workspace manifest (#1073): the `WorkspaceManifestService`, the `/workspace/*` routes (a request now gets `404`) and the `workspace_manifest_get`/`_write`/`_delete` desktop commands are removed, and the `workspace_write` row leaves the command ledger. The host no longer opens or locks `<data dir>/workspace-manifests`; an existing folder is left untouched on disk. `--workspace-manifests-dir` is now a removed flag: still accepted, ignored, one startup warning.
- **Server** — The first device that adopts the store receives the retired workspace manifests once (#1073): each manifest is converted to that device's `workspace/<projectId>` record (terminals first, then editors, as tabs; dangling ids dropped) only where the device has none, in the same write as the adoption, and the `workspace-manifests` folder is then renamed to `workspace-manifests.imported-<unix time>` as a backup (never deleted). A manifest that is corrupt, from a newer schema or unreadable is skipped with a warning and left in place. A parked pre-v2 `editor-state/<projectId>` key is adopted as `workspace/<projectId>`. A store that adopted under an earlier release keeps its `device/<id>/editor-state/*` keys and imports no manifests.
- **Desktop** — The desktop's own store renames its `editor-state/<projectId>` keys to `workspace/<projectId>` the first time it loads, so a project keeps its open files and pane layout.
- **Client** — Panes of projects you visited stay mounted and hidden, so switching back keeps terminals and chats running without a remount; hidden projects do not re-render while another project is on screen. A hidden project's editor tabs and agent launcher are not drawn until you return to it

### Bug Fixes
- **Web** — A stopped host no longer looks like an endless reconnect loop: a `Close(1001)` on `/ws`, `/terminal/ws` or the persistence socket puts the client in a `host-offline` state with no backoff loop. The status bar, the terminal overlay and the chat panel show "Host offline" (announced to screen readers) with a Retry action, and the client asks `GET /health` every 15 s, on retry, on wake and when the network returns, then reconnects when the host answers
- **Web** — The explorer's live refresh uses the host `fs` watch: `watchDirectory` maps the directory to its registered project and watches it once per project through the watch client (which asks again after a reconnect or a lost delta; a later `fs` state refreshes every watched directory), and a watch the host ends or refuses is re-armed with backoff. A watch that cannot be set up is logged and the explorer still loads without live refresh
- **Desktop** — Navigation no longer pushes the active project as the host default or syncs the MCP registry file. The project-list sync keeps the host's current default while that project is still valid (so a default set from the web or by the explicit set-default action is never reverted by a later list change), otherwise takes the stored default, else the first switchable project, derived atomically under the registry lock; the MCP registry file is mirrored when the host's effective default changes
- **Web** — Client transport hygiene (#1065): returning from the background probes the held `/ws` socket and reconnects only if the probe fails (no forced reconnect after 30 s hidden); `/ws`, `/terminal/ws` and the persistence socket each time out a stalled upgrade/authenticate at ~10 s (persistence callers and `flushPendingWrites` no longer hang); reconnect backoff is exponential with ±25 % jitter, reset only after 60 s of stable connection, and wake/online/focus cut a pending backoff short; request timers are per type (install ≥ 330 s, catalog refresh/session open ≥ 90 s); one failing session resubscribe retries and degrades alone instead of tearing the socket down; a terminal re-attach that times out on an open socket recycles the connection instead of buffering input forever
- **Chat** — A prompt whose reply is lost to a dropped connection stays open as a non-error "Waiting to confirm…" state and is resent with the SAME turn id after reconnect (only an explicit server rejection fails it); prompt receipts never end a turn; `error`/`timeout`/`crashed` turn terminators end the turn idempotently; transcript flushes are tiered (watched session ≤ ~30 ms on rAF, background ~100 ms, approvals/questions immediate, all on `visibilitychange`); an open code fence larger than 8 000 chars is no longer re-highlighted in full on every commit (highlighted once when the fence closes) (#1065).
- **ACP** — A resend of a prompt with the same `turnId` (web `send_prompt` and desktop `acp_send_prompt`) returns an `in_progress`/`accepted` receipt instead of `rate_limited`/`stale`; every accepted turn ends with exactly one `prompt_complete` (new `error`, `timeout` and `crashed` stop reasons); the durable `user_prompt` is sequenced when the driver accepts the prompt, so it is never delivered after a chunk of its turn and a rejected prompt leaves no record (#1065)
- **Server** — `POST /mcp-servers/probe` and `POST /acp/factory-key` now require the same write posture as every other mutation route; the idle agent reaper disposes only ephemeral sessions and now reaps idle durable-session agents; a terminal re-attach releases the previous attachment; session JSONL records are written in one write and a valid but unterminated tail is repaired on open; detaching a web-listed PTY re-stamps its listing time (#1065)
- **ACP** — `session/load`/`session/resume` on a session owned by a DIFFERENT live agent mid-turn are rejected (`session_owned_by_other`) instead of creating a split-brain where both agents accept prompts (#837)
- **ACP** — Web page load no longer prewarms a default agent: selection defaults to configured agents only and the launcher prepares a process only for a configured agent on composer open — Codex `npx` trees are no longer spawned on every reload (#840)
- **ACP** — Agent `browser` tool failures now emit a durable host-boundary log line (wire error code + action + argument key names + agent ID + redacted session ID, never argument values or error messages; CWE-532)
- **Web** — A reload at `#/c/<sessionId>` now lands on the running chat instead of the restored terminal: ChatRoute re-delegates tab activation after the boot layout restore replaces the pane tree (gated so user tab/focus intent and closed chats are never hijacked)
- **Web** — The termul-server web launcher's chat composer now shows the worktree isolation picker for git-repo projects (same as the desktop): a successful `git/commit-context` probe stamps `isGitRepo` (the worktree reconciler is desktop-only and `ProjectSummary` carries no git fields), and the project mirror preserves the flag across `projects_changed` refetches

### Performance
- **ACP** — Bound live transcript memory for long agent chats: over-limit sessions now trim to the 300-message live window after a background durability probe confirms host-owned history (lossless; `live_only` sessions never trim)
- **ACP** — Cap live tool calls at 500 per session (oldest finished calls drop, in-flight always retained; install paths capped too) and clamp oversized string `rawOutput` to 32 KiB + truncation marker on live update
- **ACP** — Cap payload-cache pins at 8 with project-switch unpin; amortize coalesced streaming text merges to O(delta) per frame instead of per-chunk full-text copies
- **Terminal** — Coalesce PTY appends to one `appendTranscript` per terminal per frame, with a 250ms timer backstop for hidden windows and an unmount drain failure log
- **Server** — Serve the web bundle with gzip compression (`Accept-Encoding`-negotiated; #857) and pin Vite-hashed `/assets/*` with `Cache-Control: public, max-age=31536000, immutable` on the disk `ServeDir` path (the embedded path already did) — cold load drops from 3.66 MB to ~0.98 MB on the wire
- **Web** — Memoize `GET /acp/catalog` client-side: in-flight dedupe + 2s staleness window at the facade boundary (#844). Transcript-driven re-renders no longer re-fetch the catalog (~400 req/s peak during a streaming turn); explicit refresh and opt-in toggles still bypass/invalidate

### Bug Fixes
- **Web** — A timed-out `send_prompt` (socket dropped mid-turn) no longer toasts a send failure: the outcome is unknown until replay delivers `prompt_complete`, so the generic error is downgraded to a transient host log (#844)
- **ACP** — A rejected durability probe releases its slot so the next over-limit flush retries; probe bookkeeping and clamp-log dedup are cleared on session drop (no phantom pins, no pin resurrection)
