# QA Report — termul-server E2E (terminal · ACP UI · persistence/resumability)

**Date:** 2026-09-15
**Target:** `termul-server` release build (≈ dev HEAD `73cea956`), systemd unit on `0.0.0.0:8080` with `--allow-remote-writes`, `--project-root /root`, `--sessions-dir /root/.local/state/termul/sessions`
**Method:** protocol-level WS probes (`/ws`, `/terminal/ws`) + browser UI tests on headless Chrome 150; PTY/ACP/persistence verified end-to-end including a live `systemctl restart termul-server`.
**Test agents:** ProtocolQA (protocol/persistence, evidence logs `/tmp/qa/*.log`), BrowserUiQA (UI, screenshots `/tmp/qa-ui-*.png`, `/tmp/qa-ui2-*.png`).

**Environment note:** the Obscura headless browser could not be used for UI QA — its page-side WebSocket receive is broken (opens+sends, never receives; verified against a raw in-page WS), which silently kills every WS-dependent flow. All UI results below come from Chrome 150. Obscura served well for REST/render-level checks. This is an Obscura bug to track, not a termul finding.

---

## Verdict

Core claims **hold**: terminal E2E (spawn → IO → resize → reload reattach → scrollback replay) passes; ACP session lifecycle passes at protocol level (streamed chunks → `prompt_complete`, capability gating, concurrency `rate_limited`); persisted sessions survive a server restart with identical `messageCount`/`lastSeq` and remain resumable post-restart; the server-side store survives restart. **Stability risks are concentrated in auth/deployment posture, error-state UX, and reconnect UX.**

## Findings

### P1 — Unauthenticated remote shell: any token accepted on `/ws`; `/terminal/ws` has no auth; server binds 0.0.0.0
- **Repro:** `ws://host:8080/ws` → `authenticate {token:'WRONG'}` → `ok:true`. Fresh `ws://host:8080/terminal/ws` → `spawn` with no credential → returns a root shell (`{"success":true,"data":{"id":"terminal-…","shell":"/bin/bash","pid":…}}`).
- **Expected:** token validation, or localhost-only bind until Epic 2 auth ships.
- **Evidence:** server logs `WARN … No web auth is enforced yet (Epic 2)`; `terminal_ws.rs` docstring: "Authentication is not implemented yet; never expose it to an untrusted network." The deployment (`0.0.0.0` + `--allow-remote-writes`) contradicts the code's own warning.

### P1 — Server restart wipes the project registry (projects are memory-only in this deployment)
- **Repro:** create/verify a project in `GET /projects` → `systemctl restart termul-server` → `GET /projects` → `[]`.
- **Root cause:** `FileProjectRegistry` only wired when `--projects-file`/`TERMUL_PROJECTS_FILE` is set (`server_main.rs:226-245`); the onboarding-generated systemd unit never sets it. Sessions and store DO survive the same restart — projects alone vanish, unrecoverable.
- **Note:** the web "Create New Project" dialog discloses "saved for this session only", but the consequence (total project loss on any restart) is severe for a project-aware terminal.

### P1 — ACP multi-auth method selection is a dead loop (UI)
- **Repro:** launcher with a multi-auth agent (Codex) → click "API Key" or "ChatGPT".
- **Observed:** first click re-toasts the stale `AmbiguousAuthError`; further clicks are complete no-ops — zero `authenticate` frames leave the client. Auth can never progress. Suspected: `liveAgentId` null after the multi-auth prepare failure, or wedged `inFlightAuth` dedup. (`AgentLauncher.tsx:840-858`, `acp-store.ts:2967-2982`.)
- **Evidence:** `/tmp/qa-ui2-13-auth-dialog-full.png`, `/tmp/qa-ui2-14-auth-buttons-deadend.png` + WS frame capture (no auth frames across 3 clicks).

### P2 — Failed agent chat degrades to a dead end; corpse tab persists across reloads (UI)
- Retry after a session failure toasts circular "Could not retry. Try again.", the explanatory banner disappears, composer locks behind "Session closed", no Reconnect affordance (the one in `AgentChatPanel.tsx:464-472` doesn't cover this path). Sidebar says "No chats yet" while the dead chat tab is open; after reload the tab restores showing "No active chat for this pane."
- **Evidence:** `/tmp/qa-ui2-08-agent-error-banner.png` (good initial error state), `/tmp/qa-ui2-09-session-closed-deadend.png`, `/tmp/qa-ui2-10-no-chats-sidebar.png`, `/tmp/qa-ui2-11-dead-chat-tab-after-reload.png`.

### P2 — No global connection-health surface; offline terminal input silently lost (UI)
- A 60s+ full outage shows **no banner/badge/toast anywhere**; boot with `/ws` blocked renders a healthy-looking UI with Explorer stuck on "Loading…". Keystrokes typed during an outage vanish (no echo, no buffering, no warning); the terminal channel itself auto-recovers on restore. Explorer never retries after recovery until manual Refresh. `AgentConnectionLamp` exists but only inside chat panels.
- **Evidence:** `/tmp/qa-ui2-16-offline-input-lost.png`, `/tmp/qa-ui2-15-terminal-recovered-after-outage.png`, `/tmp/qa-ui2-17-explorer-recovered-after-manual-refresh.png`.
- Related: terminal spawn silently no-ops forever if the WS handshake never completes (the request timeout arms only after `connect()` resolves) — `web-terminal-api.ts:76-122`.

### P2 — No responsive layout at phone width (UI)
- At 390×844: PROJECTS sidebar + EXPLORER stay pinned, crushing the workspace to ~0px; no drawers/bottom-nav/hamburger; content silently clipped. (`index.html` already carries mobile OSK-viewport work, so mobile web is an intended target.)
- **Evidence:** `/tmp/qa-ui-06-mobile-390.png`.

### P2 — Agent-side auth failure misclassified as `not_implemented`
- `create_session` against a real agent without provider credentials returns `{"err":{"code":"not_implemented","message":"Authentication required"}}`. `not_implemented` tells clients the feature doesn't exist, misrouting error UX. Root cause: `acp_err_to_reply` falls back to `NotImplemented` for unrecognized agent errors.

### P2 — `open_persisted_session` mutates persisted metadata (read with write side effects)
- Opening flips on-disk `status:"closed"`→`"active"` and bumps `lastActivityAt`; no agent attached. Heals only on server restart (`recover()`). Recency ordering changes on a pure read; `status` lies about liveness for the process lifetime.

### P2 — Persisted transcript duplication after session load-replay
- Session `01a06d63…`: 68-record log now contains `session_created` at seq 65 plus seqs 66–67 duplicating the merged content of seqs 2–57/58–63 verbatim; `get_session_payload` materializes the duplicated pairs (`snapshot:thought:2` ≡ `snapshot:thought:66`, etc.), so the renderer shows the same thought+answer twice. Server appends agent-replayed history on `session/load` without dedupe/reset.

### P3 — Protocol & polish
- Binary WS frame on `/ws` kills the connection with no close handshake; the structured error is enqueued but never delivered (races teardown). Send Close(1003) after flushing the error.
- `subscribe` to a nonexistent session succeeds silently (`{replayed:0}`) while `get_session_payload` correctly 404s — inconsistent.
- `list_agents` returns bare UUIDs — no name/configId/namespace/capabilities; a reconnecting client can't map IDs without having seen the spawn reply.
- Store: no per-value size cap (1MB string accepted), empty key accepted. (Good: `deny_unknown_fields`, missing `value` rejected, delete returns `{existed}`.)
- PTY attach `snapshot.cwd` is `null` though cwd is known server-side — renderer shows empty cwd until first tracking event.
- Unknown-type error text references "Epic 4" (stale; forwarding landed in Story 1.8). `/terminal/ws spawn` doesn't stream until `attach` — undocumented. `resume_session` does no namespace/ownership validation (mock agent could "resume" a foreign session; on-disk data unaffected).
- No delete-session WS API exists — QA's two mock sessions remain in the persisted list with no removal path.

## Verified working (no findings)
- **Terminal protocol:** spawn → echo marker + ANSI colors intact with seq progression; resize honored (`stty size` 43×132 after 132×43); disconnect preserves PTY; reattach replays from cursor; cursor replay returns only newer chunks; kill idempotent; wrong claim/unknown terminal collapse to identical `UNAUTHORIZED` (no existence leak).
- **Terminal UI (Chrome):** spawn via menu, live IO, window-resize → PTY resize follows (80×35 → 32×25), reload → reattach + full scrollback replay, two browser tabs mirror the same PTY live.
- **ACP protocol (mock agent):** spawn → create → subscribe → prompt → streamed `message_chunk`s → `prompt_complete`; concurrent turn → `rate_limited`; `cancel_prompt` idempotent; capability gate rejects `close_session` for agents without `sessionCapabilities.close`; OS caps rejected for browser clients.
- **Persistence:** 68-record transcript replays intact via `get_session_payload` / `recover_session_snapshot`; store round-trip; **restart survival: all sessions listed post-restart with identical messageCount/lastSeq; store keys intact; `recover()` heals active→closed; resume_session across restart works and post-restart prompts persist (seqs 10–14)**; zero orphaned child processes (systemd cgroup sweep).
- **UI (Chrome):** clean boot, zero console errors; agent picker (~20 agents, search, Install badges); command palette (Ctrl+K) full surface; theme apply instant and **survives reload via the WS store**; REST project creation visible to other tabs; graceful degradation labels ("Streaming search is not available in the web client", "SSH is desktop-only").
- **WS hygiene:** malformed JSON / unknown type / missing id / unknown session or agent all get structured errors without dropping the connection.

## Improvement opportunities (ranked, merged across both sweeps)
1. **Fail closed off-loopback:** block non-loopback bind without real auth (or gate every route behind the token) before any exposure. Highest leverage by far.
2. **Persist the project registry by default** (`TERMUL_PROJECTS_FILE` in the onboard unit, or default `<state dir>/projects.json`).
3. **Promote `AgentConnectionLamp` to a global status-bar indicator** + per-terminal reconnect overlay + input buffering/blocking while offline; add a spawn-level timeout so a stuck handshake can't hang terminal creation silently. (Fixes the F1/F2/F9/F10 class.)
4. **Fix the multi-auth selection path** (F6): keep `liveAgentId` through prepare's multi-auth failure, surface real send failures, drop the stale re-toast.
5. **First-class failed-session lifecycle:** history entry with failure state, working Reconnect, no persisted corpse tabs (F7/F8).
6. **Make reads read-only:** `open_persisted_session`/`subscribe` shouldn't flip persisted status; flip on resume/prompt only.
7. **Dedupe/reset the persisted event log** when an agent replays history on `session/load`.
8. **Map agent auth errors to a dedicated `agent_auth_required` code** in `acp_err_to_reply`.
9. **Explorer auto-retry on reconnect** (F11).
10. **Mobile breakpoints ≤640px:** collapse sidebar/explorer into drawers (F3).
11. Smaller: enrich `list_agents` payloads; `subscribe` → `not_found` parity; store size cap + reject empty keys; WS Close(1003) after binary-frame error; seed PTY snapshot cwd at spawn; session delete API; stale "Epic 4" error text.

## Real-agent round (opencode 1.18.25) — resumability PROVEN
The first sweep was blocked because the pre-configured agents (Codex & co.) lack provider credentials on this host. Re-run with **opencode**, installed through termul's own verified `install_acp_agent` (worked first try; binary at `/root/.local/state/termul/acp-registry-binaries/opencode/opencode`, args `["acp"]`), provider `sepintu` (OpenAI-compatible) configured in `~/.config/opencode/opencode.jsonc`.

**Protocol (evidence: `/tmp/qa/test7a-c.log`):** spawn 2.4s → `create_session` (cwd /root/termul) → prompt "Reply with the word OK" streamed `user_prompt → 7× message_chunk → prompt_complete` in 2.6s (first chunk 1.7s) → 51 real records persisted on disk → `close_session` ok → in-process `resume_session` 0.1s and the agent recalled the earlier word → **`systemctl restart termul-server` → fresh opencode spawn → `resume_session` ok in 1.7s → follow-up prompt answered from full prior context** ("the original word they asked me to reply with was 'OK'"). Context survived process death on both sides.
**UI (Chrome 150, screenshots `/tmp/qa-ui3-*.png`):** chat creation + streaming + turn-complete UX polished; single-method auth frictionless (F6's dead loop is confirmed multi-method-specific); reload → "Reconnecting to agent…" banner → composer re-enables → new turn completes — resume is functional.

### New findings from the opencode round
- **P1 — Reconnect replay corrupts the transcript (UI):** after reload+reconnect, the hidden greeting turn leaks into view, its chunks get spliced into the user-visible reply (`PINEAPPLEIt looks like your message came through empty…`), blocks duplicate 2–3×, and a streaming cursor gets stuck. Pre-reload transcript was clean. The store's replay seq-dedup (`acp-store.ts:5250+`) doesn't hold on this path. Evidence: `/tmp/qa-ui3-04…07*.png`. (Amplifies the protocol-side duplication finding.)
- **P1 — Web chat-history sidebar is non-functional:** the client never sends `list_persisted_sessions` (boot WS capture proves absence), so the sidebar permanently shows "No chats yet" although the server registry holds the sessions (verified 16 via raw WS). One-line-ish fix, large UX payoff; also un-dead-ends the failed-session recovery path.
- **P2 — `create_session` burns an LLM turn before the user types:** 25.2s session creation because opencode runs a hidden greeting turn at `session/new`; persisted transcript contains it (seqs 2–42 pre-date the first user prompt). Latency + token cost + transcript pollution; the host surfaces it synchronously with no timeout/feedback.
- **P2 — Warm-pool prepare leaks a persisted session per boot:** every web client boot fires `create_session` for the warm pool, persisting an untitled greeting session (7+ accumulated, status "active", never reaped) — registry grows unboundedly and each leak costs an LLM turn.
- **P3 — `resume_session` emits zero replay events to subscribers:** clients must separately call `get_session_payload`/`recover_session_snapshot` to render history — document it, or emit a snapshot on resume.
- **P3 — stuck streaming cursor** on the final block after reconnect (likely a facet of the replay-corruption finding).

Updated top priorities: replay/dedup correctness (trust-critical), wire the sidebar to `list_persisted_sessions`, stop persisting warm-pool sessions, then the earlier list stands.
