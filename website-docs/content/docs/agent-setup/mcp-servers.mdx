An MCP server is a small program or web service that gives an agent extra tools, for example "list open issues" or "query the database". MCP stands for Model Context Protocol. You add a server once in Termul, and Termul offers it to every new agent chat.

## Add MCP servers

You add servers by pasting JSON. Termul reads the `mcpServers` format that Claude Desktop and many MCP server READMEs use, so you can usually copy the config from the server's own docs.

1. Open Settings with `Ctrl+,` (`Cmd+,` on macOS) and click **MCP Servers**.
2. Click **Add server**.
3. Paste the JSON in **MCP JSON**.
4. Click **Save**.

![The Add MCP servers dialog with three servers pasted in: issues, docs and metrics](/screenshots/agent-setup-mcp-add.png)

You can paste many servers at once in an `mcpServers` block, or a single server object on its own. If one server in the block has a mistake, Termul adds the others and tells you which one failed.

There are three kinds of server:

- **stdio**: a program that runs on your computer. Give its `command`, and optional `args` and `env`.

  ```json
  { "mcpServers": { "issues": { "command": "npx", "args": ["-y", "@acme/issues-mcp"] } } }
  ```

- **HTTP**: a web service. Give its `url`, and optional `headers`.

  ```json
  { "mcpServers": { "docs": { "type": "http", "url": "https://docs.example.com/mcp" } } }
  ```

- **SSE**: an older kind of web service. Set `"type": "sse"` and give its `url`.

  ```json
  { "mcpServers": { "metrics": { "type": "sse", "url": "https://metrics.example.com/sse" } } }
  ```

If you leave out `type`, Termul treats a server with a `command` as stdio and a server with only a `url` as HTTP. Fields that Termul does not use are dropped.

<Callout type="warn">Termul saves `env` values and `headers` as plain text. Put a reference such as `$GITHUB_TOKEN` in the config instead of the token itself.</Callout>

## Check that a server works

Each server has a row with a colored dot.

![The MCP Servers list. The issues server has a green dot and its two tools are listed. The docs and metrics servers have red dots and say Probe failed.](/screenshots/agent-setup-mcp-list.png)

| Dot | Meaning |
| --- | --- |
| Green | Termul reached the server. |
| Red | Termul could not reach the server. Click the row's tools link to see the error. |
| Yellow | The server needs you to sign in. See [Sign in to a server](#sign-in-to-a-server). |
| Gray | Termul has not tested the server yet. |

To test a server, click its refresh button. To see the tools a server offers, click **Show tools**, or the tool count, such as **2 tools**.

When Termul tests a server, it replaces `$NAME` references in `env` with the values from the environment Termul runs in.

Use the other buttons on the row to manage the server:

- The switch turns the server on or off. Agents get only the servers that are on.
- The pencil button opens the server's JSON for editing. Edit one server object here, without the `mcpServers` wrapper.
- The trash button deletes the server.

## Sign in to a server

Some HTTP and SSE servers need you to sign in with your account on that service. Their dot turns yellow, and the row gets a **Connect** button.

1. Click **Connect**.
2. Sign in on the page that opens in your browser, and allow access.
3. Go back to Termul. The button changes to **Disconnect**, and Termul tests the server again.

In the browser version, the sign-in page opens in a new window. If nothing opens, allow pop-ups for the Termul site and try again. You have five minutes to finish signing in.

To remove the sign-in, click **Disconnect**.

## Browse the MCP catalog

Under your server list, the **MCP catalog** group lists the MCP servers in the public MCP registry. Termul ships with a copy of that list, and the line above it shows how many servers it has and the date of the copy.

- Type in **Search the MCP catalog** to filter the list. Use 8 words or fewer.
- Scroll to load more servers, or click **Load more**. If the list is still long, search to narrow it.
- If a server's row shows a **Repository** button, click it to open the server's source code in your browser. Some rows have no button.

Each server shows a state, and a short reason when it can't be installed as is:

| State | Meaning |
| --- | --- |
| Installable | Nothing else is needed on this computer to run this server. |
| Needs a runtime | Install the runtime named in the reason first, such as Node.js (npx), uv (uvx), Docker or the .NET SDK. |
| Unsupported | Termul can't run this server. The reason says why. |
| Source only | The registry lists only the source code, with no package or hosted URL to install. |

Servers that the registry marks as deprecated have a **Deprecated** badge.

### Install a server from the catalog

1. Click **Install** on an installable server.
2. If the server needs settings, such as an API key, fill in the form and click **Review**. Termul hides the values of secret fields.
3. Read the review. It shows the exact command and arguments, or the URL, that Termul will save, with each environment variable and header. Click **Approve** to install, or **Cancel** to save nothing.
4. Termul adds the server to your list, turned on, and checks that it responds. If the server asks you to sign in, click **Sign in** to open its sign-in page in your browser.

A server you installed shows **Installed** in the catalog. **Install** stays off for servers that aren't installable, and on a connection that can only view. In the browser version, open a project first, because each project has its own list.

If the review waits too long or something changes on the host, Termul saves nothing and offers **Start over**.

<Callout type="warn">Termul saves the values you enter, API keys included, as plain text with the server's settings.</Callout>

## Choose servers for a new chat

When you start a new chat, the chat box shows how many MCP servers the chat gets. Click that count to see each server's status and turn servers on or off. The switches there are the same switches as in Settings, so the change applies to later chats too.

Termul always offers stdio servers. It offers HTTP and SSE servers only to agents that say they support them.
