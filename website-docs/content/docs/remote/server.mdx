`troupe-server` is Troupe without a window. It runs your agents, terminals and git on one machine and serves the Troupe app to any browser that connects to it. Use it on a home server, a cloud machine, or your own computer.

## Install the server

You can install the server as a single program file or run it in Docker.

<Tabs items={['Linux binary', 'Docker']}>
<Tab value="Linux binary">

Release builds are for Linux on x64 and arm64. Download the one that matches your machine:

```bash
case "$(uname -m)" in
	x86_64)        asset=troupe-server ;;
	aarch64|arm64) asset=troupe-server-linux-aarch64 ;;
	*) echo "Unsupported architecture: $(uname -m)" >&2; exit 1 ;;
esac
curl -fL -o troupe-server "https://github.com/gnoviawan/termul/releases/latest/download/$asset"
chmod +x troupe-server
```

The builds need glibc 2.35 or newer, which Ubuntu 22.04 and later have. Distributions that use musl instead of glibc, such as Alpine, aren't supported.

The link above gets the latest stable release. For the nightly build, download from `https://github.com/gnoviawan/termul/releases/download/nightly/$asset` instead.

Move the file to a folder on your `PATH`, such as `~/.local/bin`, so you can run `troupe-server` from anywhere.

Versions before 0.5.0 called the program `termul-server`. If you already run it, you don't need to reinstall: updates replace the `termul-server` file in place, and your service and scripts keep working.

</Tab>
<Tab value="Docker">

The Troupe repository has a `Dockerfile` and a `docker-compose.yml`. The image is `ghcr.io/gnoviawan/troupe-server`.

1. Copy `docker-compose.yml` from the Troupe repository into a new folder.
2. In that folder, create the folder for your projects:

	```bash
	mkdir -p workspace
	```

3. Start the container:

	```bash
	docker compose up -d
	```

4. Read the access token:

	```bash
	docker compose exec termul-server cat /home/termul/.local/state/termul/web-auth-token
	```

5. Open `http://localhost:8080/#token=<token>` in your browser, with the token in place of `<token>`.
6. Add `/workspace`, or a folder inside it, as a project.

Things to know about the container:

- The server can see only the `workspace` folder. Your projects must be inside it.
- The port is open on `127.0.0.1` only. To reach it from other devices, put an HTTPS reverse proxy in front of it. See [Put a reverse proxy in front](/docs/remote/server-options#put-a-reverse-proxy-in-front).
- The compose file turns on remote changes (`TERMUL_SERVER_ALLOW_REMOTE_WRITES=true`), because browser traffic reaches the container from the Docker network, not from the container itself.
- The image has no agent programs such as Claude Code or Codex. Install them into `/home/termul/.local/bin` inside the container. That folder is on the `PATH` and is kept between restarts.
- The user inside the container has user ID 1000. If your own user ID is different, build the image with yours before the first start: `TROUPE_UID=$(id -u) TROUPE_GID=$(id -g) docker compose up -d --build`.
- To set your own token, put `TROUPE_WEB_AUTH_TOKEN=<token>` in a `.env` file next to `docker-compose.yml`.
- The older `TERMUL_*` name of each variable still works. If you set both, the `TROUPE_*` name wins unless it is blank (empty or only spaces). An existing `.env` file keeps working.

To update, pull the new image and restart:

```bash
docker compose pull
docker compose up -d
```

To follow the nightly builds, set `TROUPE_IMAGE=ghcr.io/gnoviawan/troupe-server:nightly` in `.env`.

</Tab>
</Tabs>

## Set it up in the browser

A fresh `troupe-server` has no settings yet, so the first run serves a setup page instead of the app. While it waits for you, the server listens on every network interface, so you can open the page from another device.

<Steps>
<Step>

### Start the server

Run this in a terminal on the server:

```bash
troupe-server
```

The server prints a setup link to the terminal, or to the service's journal, and waits:

```text
http://<server-address>:8080/?setup=<token>
```

The `?setup=` part is a one-time key for this run. Without it the setup page stays closed, so only someone who can read the server's output can finish the setup.

</Step>
<Step>

### Answer the questions

Open the link in a browser. The setup page asks for:

- **Bind host.** Keep `127.0.0.1` to allow only this machine, for example behind a reverse proxy. Pick `0.0.0.0` to accept connections from other devices.
- **Bind port.** The default is `8080`.
- **Allow changes from other devices.** Shown when the host is `0.0.0.0`. Turn it on to let other devices make changes. See [Allow changes from other devices](/docs/remote/server-options#allow-changes-from-other-devices).
- **Update channel.** `stable`, `insider`, `nightly`, or `none`. See [Update the server](/docs/remote/server-options#update-the-server).

The **Advanced** section holds the **sessions directory** (where Troupe keeps chat history), the **projects registry file** (your project list), and how often the server checks for updates. The defaults are in `~/.local/state/termul`.

The page checks each answer and shows mistakes next to its field, so nothing is saved until everything is valid.

</Step>
<Step>

### Let the server restart

Applying saves your answers to `server-config.json` in the server's state folder. The server restarts itself on the address you picked, your browser follows it there, and you land in the normal Troupe app.

When the host is `0.0.0.0`, the server also creates an access token and hands it to your browser on the way. Other browsers and devices still need it. See [The access token](/docs/remote/server-options#the-access-token).

</Step>
</Steps>

To change these settings later, open **Settings** in the browser (`Alt+,`) and select **Server**. It is the same page filled in with the current settings. Applying them saves the file and restarts the server again, and the browser follows when the address changes. The **Server** tab is in the browser version only.

For the settings it holds, `server-config.json` wins over flags and environment variables, so reconfiguring works even on a server whose service still passes old flags. If the file ever becomes unreadable, the server logs an error and goes back to the setup page instead of locking you out.

### Set it up in the terminal instead

`troupe-server onboard` asks the same questions in a terminal and writes the same `server-config.json` — both paths produce identical settings. Use it for scripted or headless installs, or when you want the wizard to install the server as a service so it keeps running after you log out of SSH:

```bash
troupe-server onboard
```

Press Enter at any question to keep the default shown in brackets. When the wizard finishes, it starts the server and prints its address, how to read the logs, and how to stop it.

The wizard may also offer to write a settings file, `termul-server.env`, in the state folder. Answer `y` so the background server gets the same settings.

On machines with systemd, the wizard installs a `troupe-server` service. When you run it as root, it is a system service and you manage it with `systemctl stop troupe-server` and `journalctl -u troupe-server -f`. As another user, it is a user service, so add `--user` to both commands. If the machine already has the `termul-server` service from an earlier version, the wizard updates that service instead, so keep using `termul-server` in those commands.

On machines without systemd, the wizard starts the server as a background process. The log is `termul-server.log` and the process ID is in `termul-server.pid`, both in the state folder. A background process doesn't restart after a crash or a reboot.

## Start the server by hand

To try the server, run it in the foreground:

```bash
troupe-server
```

On a server that is already set up, this serves Troupe at `http://localhost:8080` for browsers on the same machine. On a fresh install it starts the setup page described above instead. Press `Ctrl+C` to stop it.

To let phones and other computers connect, listen on all network interfaces:

```bash
troupe-server --host 0.0.0.0 --port 8080
```

Flags such as `--host` and `--port` count as a configuration, so a fresh install started this way skips the setup page. Once a `server-config.json` exists it wins over these flags for the settings it holds — change those under **Settings**, in the **Server** tab, instead. Flags the file doesn't cover, such as `--allowed-origins`, still apply.

The first time the server listens on `0.0.0.0` without a token, it creates an access token and prints the path of the file that holds it. Read the token from that file, then open `http://<server-address>:8080/#token=<token>`. See [The access token](/docs/remote/server-options#the-access-token).

Plain `http://` sends the token and everything else unencrypted over the network. Use it only on a network you trust. For anything else, put an HTTPS reverse proxy in front of the server.

## Add your first project

A new server has no projects.

1. Open the server's address in a browser.
2. Click **+** next to **PROJECTS**, then click **New project**. You can also press `Alt+N`.
3. Click **Browse**. Troupe opens a folder picker that shows the folders on the server, not on your own device.
4. Go to the project folder and select it, then create the project.

The server saves the project in its projects file, so it is still there after the server restarts.

For the rest of the project setup, see [Getting started](/docs/getting-started).
